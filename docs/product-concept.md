# Tsumu — プロダクトコンセプト

この文書は最初に提示されたプロダクト構想を保存したもの。実装範囲は [開発計画](roadmap.md)、技術的な制約は [アーキテクチャ](architecture.md) を参照する。ここにある全機能を一度に実装しない。

## コンセプト

**前回の自分を基準に、短いトレーニングを積み重ねる。**

Tsumuは、ジムでのトレーニングを簡単に記録し、自分の成長を実感するための個人向けWebアプリ。
高度なトレーニング管理や本格的なボディメイクよりも、「今日は何をやるか」「前回どのくらいできたか」「少しずつ成長できているか」を分かるようにし、継続のモチベーションにつなげる。

## 解決したい課題

利用者は週2〜3回、平日を中心に30分程度ジムを利用する。ストレッチ、ランニング、ジムの機材をその日の気分で利用しているが、記録がないため自分の基準が分からない。

- 前回より成長したのか分からない。
- どの程度の重量・回数を目指せばいいか分からない。
- その日に何をトレーニングするか毎回考える。

日々の小さなトレーニングを蓄積し、次のトレーニングにつながる記録を残す。

## 基本方針

### ジムでは簡単に

スマートフォンで **種目 → 重量・回数 → 完了** を素早く入力する。前回実績と今回の目標を同じ画面に表示し、過去履歴を探す手間をなくす。細かな管理操作を要求せず、シンプルでスタイリッシュなUIを目指す。

### 家では詳しく

PCやスマートフォンから種目・機材・ルーティンを設定し、過去のトレーニング、体重、成長グラフを確認する。「ジムで使う画面」と「管理・振り返り画面」の役割を分ける。

## トレーニングの開始

### ルーティンから開始

複数のルーティンを登録し、その日の時間や気分で選択する。

- 30分基本メニュー
- 上半身
- 有酸素＋軽め
- 時間がない日の15分

ルーティンには主に種目と目標セット数を登録する。重量・回数を固定するのではなく、開始時に前回実績や次回目標を提示する。

### フリーで開始

ルーティンを使わず、その場で好きな種目を追加する。気分でトレーニングする日にも対応する。

## 機材と種目

別の概念として管理する。一つの機材を複数の種目で利用できる。複数店舗への対応は行わない。

### 機材

例：チェストプレス、ケーブルマシン、トレッドミル。

| 項目 | 内容 |
| --- | --- |
| 名前 | チェストプレスなど |
| カテゴリ | マシン、フリーウェイト、有酸素など |
| 単位 | kgなど |
| 増分 | 5kgなど |

### 種目

例：チェストプレス、ケーブルフライ、トライセプスプッシュダウン、ランニング。

| 項目 | 内容 |
| --- | --- |
| 名前 | 種目名 |
| 使用機材 | 任意 |
| 主対象部位 | 胸など |
| 副対象部位 | 上腕三頭筋など |
| 記録方式 | 重量＋回数、時間、時間＋距離など |

身体の部位は機材ではなく種目に紐づける。

## 記録方式

| 種類 | 記録内容 |
| --- | --- |
| 筋力トレーニング | 重量・回数・セット |
| ランニング | 時間・距離 |
| ストレッチ | 時間 |
| その他の有酸素 | 時間を基本とする |

トレーニングや種目に簡単なメモを残せるようにする。メモはMVPでは補助機能とし、操作の中心に置かない。

## 前回実績

トレーニング中に、その種目の前回実績をセット単位で表示する。

例：チェストプレスの前回実績が「30kg × 10回、30kg × 10回、30kg × 8回」であれば、そのまま今回の入力画面に表示する。履歴を探さなくても、その日の基準を持てるようにする。

## 次回目標

前回実績に基づき、単純なルールで次回目標を提案する。あくまで参考で、従う必要はない。機材の重量増分も使う。

- 30kg × 10回 × 3セットを達成した場合：「次回は35kgを試してみる」。
- 30kgで10回・8回・6回だった場合：「30kg × 10回 × 3セットを目指す」。

これらはコンセプト上の例であり、全種目に適用する確定アルゴリズムではない。具体的な増量条件は実装前に決める。

## 成長の可視化

全体の高度な分析よりも、種目ごとの小さな成長を分かりやすく伝える。

- 前回実績
- 自己ベスト
- 重量の推移
- 回数の推移
- 最近のトレーニング履歴

「前回より5kg増えた」などの変化を伝える。自己ベストやグラフの集計定義は該当機能の実装時に決定する。

## トレーニング完了

保存完了だけでなく、その日の成果を表示する。

> 今日も積みました
>
> トレーニング時間：28分／4種目
>
> チェストプレス：30kg → 35kg
>
> 次回目標：35kg × 10回

これは表示イメージ。Tsumuの名前に合わせ、「今日も少し積み上げた」という感覚を作る。

## 体重管理

測定した日に手動入力し、時系列で確認する。毎日の入力を前提としない。トレーニング記録とは独立して管理する。Fitbitとの自動連携は将来の候補。

## 休憩タイマー

セット間の休憩を計測する機能は低優先度。なくてもMVPは成立する。

## MVP全体の対象

- ユーザー認証
- 機材の登録・編集
- 種目の登録・編集
- ルーティンの複数登録・編集
- ルーティンからトレーニング開始
- フリートレーニング
- 重量・回数・セットの記録
- 時間の記録
- ランニングの時間・距離記録
- 前回実績表示
- 次回目標の提案
- トレーニング履歴
- 種目ごとの履歴
- 種目ごとの成長表示
- 体重の手入力と履歴
- 簡単なメモ
- スマートフォン向けトレーニングUI
- PCでも利用しやすい管理・振り返りUI

## MVPに含めないもの

AIによるメニュー生成、高度な分析、SNS、ランキング、他ユーザーとの共有、複数店舗管理、食事・カロリー管理、本格的な健康管理。

## 将来的な候補

Fitbit連携、心拍数との連携、体重の自動取得、休憩タイマー、継続状況の可視化、最近の実績を加味した目標、ルーティンごとの分析、部位ごとのトレーニング状況。

## ユーザー境界

当面は個人利用のみで、サービスとしての一般公開を目的にしない。ただし最初からUser境界を持ち、各種データはユーザーに紐づける。他ユーザーのデータを参照・更新できないようにする。

## 想定する主要画面

| 画面 | 主な役割 |
| --- | --- |
| Today | 今日のトレーニングを開始する |
| Routine | ルーティンを選択・管理する |
| Workout | ジムでトレーニングを記録する |
| Workout Result | その日の成果を確認する |
| History | 過去のトレーニングを見る |
| Exercise | 種目ごとの成長を見る |
| Body | 体重を記録・確認する |
| Settings | 機材・種目などを管理する |

スマートフォンの主要ナビゲーションはToday / History / Progressあたりを想定し、設定系の優先度を下げる。最終的なナビゲーションはUI実装時に決める。

## 判断の基準

詳細な記録そのものを目的にせず、次につながる最低限の記録を残す。「ジムで迷わず入力できる」「前回の自分がすぐ分かる」「少し成長したことが分かる」を優先する。

**記録する → 成長が分かる → 次の目標ができる → またジムに行く。**
